# Alem frozen-policy local controller prototype

This is a CPU-only, decentralized RL-controller interface, not an LLM team or a leaderboard replication. Candidate code is never imported on the host or in the trusted environment/policy process. Three network-disabled Docker containers each load the same `candidate/controller.py`, with independent processes, memory, filesystem and IPC. No training or LLM inference occurs during controller evaluation; the frozen recurrent RL policy performs its usual forward pass.

```python
def initialize(agent_id: int, schema: dict):
    return {}  # JSON memory, <=65536 encoded bytes

def act(local: dict, memory):
    return {"action": local["proposal"], "memory": memory}
```

`agent_id` is 0, 1 or 2. `schema` contains observation_size, action_count, native_comm_action_ids and max_memory_bytes. Every `local` has precisely observation (list of floats), legal_mask (list of booleans), frozen_logits (list of floats), proposal (integer), previous_reward (this actor's reward, initially zero) and step (zero-based local episode step). Observation is the unchanged official symbolic vector with the official self-ID suffix. It includes the native teammate dashboard; no native visible feature is removed. It does not contain raw EnvState, global map, world ID, environment RNG, peer observation arrays or evaluator scoring counters.

All actions allowed by the official mask may be returned. There is no top-k or override quota. The four native communication actions are the final four action IDs and consume the actor's game action. There is no separate controller messaging channel, shared memory or shared writable directory. Own state persists within an episode and resets with new controller containers at the next episode. Module globals are possible within the process memory cap; the declared JSON memory is separately bounded. Per-step requests and replies use bounded framed JSON; large arrays travel as base64 numeric bytes and are decoded inside the controller process, without pickle.

The trusted evaluator advances the frozen HyperMARL GRU on the actual local observations once per actor per environment step. Overriding a proposal does not stop/reset its recurrent state or replace its observations. The official frozen eval uses masked categorical **mode**, not sampling. Frozen weights are never writable by controller processes. Controller containers receive no source, weights, output directory, Docker socket or host home directory.

World generation uses `PRNGKey(world_id)`. A new declared episode transition stream is `fold_in(PRNGKey(0xA1E00001), world_id)` and each step performs the native three-way split `(next_rng, action_rng, environment_rng)`. The action stream is unused by the native deterministic mode but remains explicit. This is a separate protocol from the official evaluator, which carries its transition stream across episodes; old results remain separate. Controllers never receive these keys or world ID.

The separately sealed prototype compared one world (9999), preserving the10000-step ceiling/natural termination, between a trusted native-equivalent greedy loop and the same loop routed through three isolated pass-through controllers. Every state, observation, recurrent-state, action, reward, done and RNG fingerprint matched for863steps. See `prototype-parity.json`, including both earlier harness failures. This establishes transport parity under the declared RNG, not controller quality or broad benchmark readiness.

This portable runner evaluates **only the submitted controller** on one fixed suite: `dev` worlds20000–20003 or `evaluation` worlds9999–10018. All episodes retain the10000-step ceiling and natural termination. One trusted engine amortizes checkpoint loading/JIT; all three worker containers are destroyed and freshly created for EVERY world, so globals, files and local RNG state cannot persist across episodes. The evaluation worlds are public canonical worlds, not secret test data. The engine never sends their IDs to workers, but observations could still identify familiar worlds. Do not claim protected heldout generalization.

Every world yields a row, including candidate-invalid or infrastructure/incomplete outcomes. Primary score is the mean native `Team/coord_reward_pct_of_max` fraction only when all prescribed worlds are scored; otherwise null. This is normalized reward, not a pass rate. Base/total reward and native coordination subcategories accompany it. No native baseline rollout repeats during a candidate submission: baseline is the same runner with `reference/controller.py`, which passes through each official proposal.

The operator cap is10800seconds, with30seconds per worker response as a safety bound. Timeout is unscored and preserves completed diagnostics; it is not a failed-game zero. One-world parity measured19.2seconds for863 isolated rounds versus3.1seconds for the warmed trusted loop, plus startup/restore/JIT. At that rate20 full10000-step episodes could require roughly4450seconds before startup; this is a provisional extrapolation, not a runtime guarantee. Slower controllers can cost more. Do not infer repeated research-loop feasibility from the much faster native-only evaluator.

Workers are standard-library-only in the current pinned Python image. Candidate randomness is initialized reproducibly, but Python code can access other entropy/time; fixed environment RNG alone does not guarantee deterministic arbitrary candidates. Claim deterministic results only after repeated-run checks or a declared deterministic candidate contract. Exception text stays in local diagnostics; public summaries expose bounded types/codes. The candidate artifact is one controller.py file; no external inference services are available.

The existing image, source commit, weights revision and source/asset hashes are recorded before and after execution. The vendor source and existing pilot are read-only. Hard difficulty and SCALE_BASE_DIFFICULTY=false match the current baseline20 protocol; this differs from historical checkpoint-training settings. Startup/restore/JIT, trusted-loop time, IPC/adapter time, controller bytes and container overhead are reported separately where measurable.

Security limits: Docker provides process/mount/network isolation, with non-root controllers, dropped capabilities, no-new-privileges, read-only roots, private tmpfs and hard no-fork resource limit. The trusted host relay still has Docker authority and all three packets; it is evaluator-owned. Docker/kernel or same-host timing side channels are not eliminated. This local prototype is not proof of tamper-proof execution in OpenRSI's shared Work-snapshot Judge: inherited interpreter/libraries remain a material residual limitation there.
